# Security policy

## Supported versions

Only the latest released version is supported with security fixes while the project is in the
`0.x` development series.

## Reporting

Use GitHub private vulnerability reporting or open a private GitHub Security Advisory when the
repository enables those features. Do not publish exploit details in a public issue before a fix
is available.

Include:

- affected version and operating system;
- installation mode;
- reproduction steps;
- expected and observed behavior;
- impact assessment;
- suggested mitigation, if known.

The project does not request credentials or filtered environment variables. Reports involving
secret exposure, cross-user message injection, unauthorized prompt delivery or permission bypass
should be treated as high priority.
